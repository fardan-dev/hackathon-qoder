# Sentinel — Insurance Claim Fraud Triage

Human-in-the-loop triage for P&C insurance claims. The system **flags** claims
that need investigation and explains why; a human reviewer always decides.

Built for the FSI Mini-Hackathon / take-home (scenario 04 — Insurance). The
Phase 0/1 thin slice is a rules-only, deterministic, offline-capable stack with
synthetic data. No ML, no OCR, no automatic rejection.

> Naming: **Sentinel** is the working product name in the BRD/PRD/TRD. The web
> app is branded **Triage Klaim**, and the Compose project is `claimshield`.

## Principles

1. **A flag is not proof.** The system never rejects a claim, never changes claim
   status, and never emits a risk probability. Reviewers confirm or clear.
2. **Coverage is measured, not claimed.** Every release ships a coverage matrix
   and a residual-risk register.
3. **Explainable by construction.** Each flag carries a rule ID and version, the
   triggering value, evidence references, and a plain-language explanation.
4. **Deterministic.** The same dataset and rule pack produce byte-identical
   output, independent of ground-truth labels.

## Quick start

Prerequisites: Docker Desktop with Compose v2, Go 1.24+, `make`, `curl`, `jq`.
About 4 GB of free disk is enough.

```bash
cp .env.example .env        # then change the demo passwords and tokens
make up                     # Postgres, Kafka, Redis, migrations, 8 Go services
make seed                   # demo users + 14-row coverage matrix
make datasetgen             # deterministic synthetic CSVs
make demo                   # five-minute end-to-end acceptance path
```

The demo runs: import → evaluate → alert → case + evidence package → human
decision → audit verification → coverage/dashboard → metering close → value
report → reproducible billing export.

Optional read-only web UI:

```bash
make web                    # http://localhost:3000
# log in as reviewer@claimshield.local with SEED_REVIEWER_PASSWORD from .env
```

Full operating instructions, ports, reset paths, and troubleshooting live in
[docs/RUNBOOK.md](docs/RUNBOOK.md).

## Architecture

```text
Next.js web (read-only)        Go services                     Data
──────────────────────         ───────────                     ────
session cookie  ───────────►   identity   8081  ──┐
server-side fetch              ingestion  8082    │
                               rules      8083    ├── PostgreSQL 17 (RLS per tenant)
                               alert      8084    ├── Kafka (event backbone)
                               case       8085    ├── Redis (cache + rate limit)
                               audit      8086    │
                               metering   8087    │
                               reporting  8088  ──┘
```

- **Web** never talks to the services from the browser; the opaque session token
  stays in an HttpOnly cookie and API calls are made server-side.
- **Tenant isolation** uses PostgreSQL row-level security (`ENABLE` + `FORCE`)
  plus a transaction guard; internal endpoints require an internal token.
- **Identity** stores only salted hashes; 256-bit session tokens are persisted
  as SHA-256 hashes.
- **Audit** is a hash-chained log written through the transactional outbox.
- **Metering** deduplicates usage per source event and produces checksummed,
  PII-free value and billing exports.
- **Deployment:** the TRD reference design targets Alibaba Cloud Jakarta
  (`ap-southeast-5`) across 3 AZ. The Alibaba account was disabled during the
  hackathon, so the Phase 1 landing zone was implemented on **Google Cloud
  Jakarta (`asia-southeast2`, 3 zones)** with the same failure-domain pattern.
  Bootstrap and the staging environment are applied; see
  [`infra/terraform`](infra/terraform/README.md) for current status.

## Scope

**In scope (Phase 0/1):** P&C auto and property claims; CSV/JSON import; 33
active rules in families A–G; alert queue; evidence packages; human decisions;
suppression; audit; coverage matrix; usage metering and billing export.

**Out of scope:** automatic rejection or claim write-back, ML scoring, OCR and
document forensics (family H rules are catalogued but gated off), external data,
production multi-tenant onboarding, payment processing.

## Security notes

- Never commit `.env`, Terraform state, or `terraform.tfvars`; they are ignored.
- Demo users and passwords exist only for the local thin slice. Change them
  before exposing the stack to anyone.
- All demo data is synthetic. Do not load real customer or claimant data.
- The thin slice runs over HTTP on localhost. TLS belongs at the ingress.
